### 算法亮点
- BurstSimulator 双向隔离：沿故障 pipe 两端 BFS 各找最近阀门组成关闭列表
- 隔离完整性 = source → 故障段任一端可达距离的最小值；全 source 都不可达 = Infinity
- 影响区域用凸包（Andrew's monotone chain）替代复杂多边形
- 健康评分 6 维加权（年龄25% + 材质20% + 土壤15% + 历史20% + 压力10% + 阴保10%）
- 状态处罚：damaged ×0.5, under_repair ×0.7, abandoned = 0

- 修复：用干净环境重新构建所有包：`env -u NODE_OPTIONS -u CODEBUDDY_SAFE_DELETE_ENABLED -u CODEBUDDY_SAFE_DELETE_BIN_DIR -u CODEBUDDY_SAFE_DELETE_SHIM_DIR -u GENIE_TRASH_DIR -u BASH_ENV -u PYTHONPATH pnpm -r --filter './packages/*' build`。
- **关键**：在本环境跑任何 `pnpm build`/`vitepress build` 都要 `env -u NODE_OPTIONS -u CODEBUDDY_SAFE_DELETE_* ...` 去掉 safe-delete shim，否则 tsup 清理 dist 会被拦截报 ETIMEDOUT。

### 问题 2（真正的根因）：VitePress markdown html_block 被空行切断 → SSR TypeError
- **之前记录「SSR TypeError 非致命」是错误认知**，实际会导致页面 SSR 渲染内容丢失（面板内容空白）。
- 根因链：`.md` 里 `<DemoLayout>` 组件内部多个 `<SimPanel>` 之间用**空行**分隔 → markdown-it 的 html_block 规则（自定义组件 i=6，遇到 `/^$/` 空行即结束 block）把 `<DemoLayout>` 切碎 → 第 2 个及之后的 `<SimPanel>` 被误判为 `<pre><code>` 代码块 → 代码块里的 `{{ xxx }}` 被 Vue 编译器错误编译成 `toDisplayString(_ctx.xxx)` → SSR 时 `_ctx.xxx`（onMounted 才填充的 null/undefined 变量）抛 `Cannot read properties of null/undefined`。
- **修复**：去掉 `<DemoLayout ...>` 到 `</DemoLayout>` 之间（含 `<template #map>`/`#panel` 及 SimPanel 之间）的**所有空行**，让整个组件成为连续 html_block。共修 11 个文件：compute/latency、grid/{load,outage,topology}、pipeline/{burst,nlpg}、telecom/coverage、transport/incident、water/{dam,flood,river}。
- **验证**：`pnpm build:demo` 无任何 TypeError，`build complete`；SSR 产物 dam.html/flood.html/river.html 等面板内容完整渲染。
- **结论**：VitePress 里 `.md` 写复杂 Vue 组件时，组件模板内部**不能有空行**（否则 markdown 切断 html_block）。之前记录的「`<div />` 自闭合改 `<div></div>`」不是本问题的根因（自闭合只是副作用，空行才是关键）。更彻底的方案是复杂组件抽到独立 `.vue` 文件，`.md` 里只留 `<XxxDemo/>` 单行引用。
