# 指南 · 投影与屏幕坐标（Projection）

「坐标系」（CRS）和「投影」（Projection）经常被混为一谈，但它们解决的是两个问题：CRS 回答「这组经纬度数字是哪套基准」（纠偏问题，见《坐标系与偏移纠偏》）；投影回答「球面上的点如何画到屏幕像素上」（渲染问题）。本文讲后者。

## Web Mercator：渲染层统一投影

草果地图基于 MapLibre GL，渲染层统一使用 **Web Mercator（EPSG:3857）**：经度线性映射，纬度按墨卡托公式非线性压缩（高纬度被拉伸，所以武汉的世界地图比真实比例「胖」）。

对业务开发者的意义：

- **你永远不用碰 3857 米制坐标**——引擎输入输出都是经纬度（EPSG:4326 语义），Web Mercator 只存在于渲染管线内部；
- 在纬度 30°（武汉）附近，1 屏像素对应的真实距离约为 `156543.03 / 2^zoom × cos(30°)` 米，可用这个式子估算「某 zoom 下 1px ≈ 多少米」，反过来定标注半径、缓冲距离的视觉大小。

## 经纬度 ↔ 屏幕像素

通过原生 MapLibre 实例的 `project` / `unproject` 换算：

```ts
import { Map } from '@caoguo/maplibre'

const map = new Map({ container: '#app' })
map.on('load', () => {
  const ml = map.getMap()

  // 经纬度 → 容器像素（常用于把 DOM 弹窗钉在要素上）
  const pt = ml.project([114.3055, 30.5928])   // { x, y }
  popup.style.left = `${pt.x}px`
  popup.style.top = `${pt.y}px`

  // 像素 → 经纬度（点击拾取、框选）
  const lngLat = ml.unproject([400, 300])      // LngLat { lng, lat }
})
```

> 地图平移/缩放后像素会失效，长驻 DOM 需监听 `move` 事件重算（或直接用 symbol 图层 + `Popup`，让引擎代管）。

## 3D 视角下的两个失真

开启 pitch（倾斜）与地形后，投影行为有两点变化：

1. **pitch 下 `project` 仍准确，但屏幕边缘的要素会被透视压缩**——DOM 标注可能重叠，密集区建议按 zoom 分级显隐（见 LOD）；
2. **地形模式（`enableTerrain`）下要素贴合真实高程起伏**，同一经纬度在屏幕上的位置会随高程变化——用 DOM 像素对位时务必在地形稳定后取值。

## 常见误区

::::: warning 别踩坑
- **把 3857 米制坐标（如 `[12727000, 3568000]`）当经纬度传给引擎**——地图会「飞出地球」。先确认数据是度还是米。
- **纠偏和投影混着修**：位置不对先查 CRS（声明 `dataCRS`），形状/大小不对才查投影相关设置。
- **像素坐标跨 zoom 复用**：`project` 的结果只在当前相机状态下有效。
