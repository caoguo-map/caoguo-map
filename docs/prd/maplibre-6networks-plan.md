## 零、什么是"利他服务"

本方案的"利他"定义：**降低六张网从业者的重复劳动成本，让他们把精力花在业务决策而非技术基建上。**

具体来说：
- **对开发者利他**：AI Copilot 让 GIS 开发者不再手写重复的地图代码
- **对数据工程师利他**：智能数据入图让脏数据不再需要人工清洗
- **对业务人员利他**：NLPG 让不会写 SQL 的人也能做空间查询
- **对决策者利他**：行业推演组件让"经验拍脑袋"变成"模型辅助决策"
- **对甲方利他**：开源 + 可私有化 = 安全可控 + 不被供应商锁定

## 一、六张网的共性技术底座（通用利他服务层）

六张网虽然行业不同，但在空间信息处理上有 **7 个共性技术需求**。这个共性底座是本产品最核心的竞争力——写一次，六张网复用。

### 1.1 共性需求矩阵

| # | 共性需求 | 痛点 | 利他服务 | 技术实现 |
|---|---------|------|---------|---------|
| **C1** | **Web 地图渲染引擎** | 商业引擎（SuperMap/ArcGIS）授权费高、离线能力弱、Web 端体验差 | 开源 MapLibre 定制引擎，零授权费，完整离线能力 | MapLibre GL JS + 自定义投影 + WebGL Shader 优化 |
| **C2** | **空间数据入库** | 六张网各业务系统的地址/坐标数据格式混乱、坐标系不统一 | 智能数据入图管线（GeoAI）：自动识别地址列、纠正坐标系、批量空间化 | 正则+词典+坐标库的传统 NLP 方案（不依赖大模型，保证速度和可靠性） |
| **C3** | **自然语言空间查询** | PostGIS 空间查询门槛高，业务人员无法自助 | NLPG 接口：自然语言 → PostGIS SQL → 地图结果 | LLM + SQL 校验层 + 参数化执行 + 结果可视化 |
| **C4** | **地图开发加速** | GIS 开发者写地图代码效率低，重复劳动多 | MapCopilot：自然语言生成 MapLibre 地图代码 | LLM + 组件库 API 约束 + AST 校验 + 沙箱运行 |
| **C5** | **地图样式管理** | 各甲方对地图视觉风格要求不同，样式调整耗时 | 智能样式生成 + 样式迁移：设计稿/描述 → style.json | 色板提取 + 模板匹配 + 风格参数化（降级方案，不依赖多模态大模型） |
| **C6** | **性能与渲染优化** | 大屏场景百万级要素渲染卡顿 | AI 自适应 LOD + 智能标注避让 | 帧率监测 + 动态降级策略（传统算法，非 ML） + 约束求解标注避让 |
| **C7** | **AI 调试与诊断** | 地图性能问题排查困难 | AI Debug 工具：自动分析渲染瓶颈 + 给出优化建议 | Performance Profiler 数据分析 + 规则引擎匹配常见瓶颈模式 |

### 1.3 共性层的商业价值

| 维度 | 价值 |
|------|------|
| **开发成本** | 六张网共用一套引擎 + 共性组件，每新增一张网只需开发行业专属组件，开发量减少 60-70% |
| **技术壁垒** | 共性服务层是核心 IP——竞品（超图/中地）每做一张网都要从零搭建，我们只需扩展行业组件 |
| **采购优势** | G 端采购按"平台+行业模块"报价，共性层作为平台一次性收费，行业模块按需叠加 |
| **生态效应** | 开源引擎吸引开发者 → 开发者贡献行业组件 → 组件反哺引擎 → 正向飞轮 |

## 二、各网专属方案（差异化利他服务）

在共性底座之上，每张网有独特的数据特征、业务流程和决策需求。以下逐网展开。

### 2.1 地下管网（燃气/供水/供热/排水）

> **关键词：拓扑连通性 × 物理推演 × 安全应急**

#### 行业特征

- 数据核心是 **拓扑关系**（管段→节点→设备），不是独立的点位
- 管网数据来源分散（各权属单位），格式不统一，更新频率差异大
- 安全应急是第一优先级：爆管、泄漏需要秒级响应

#### 专属组件

| 组件 | 功能 | AI 加持 |
|------|------|--------|
| `<PipelineTopology>` | 管网拓扑编辑器：可视化拖拽管段/节点/阀门，自动维护连通性 | — |
| `<BurstSimulator>` | 爆管推演：选择故障管段 → 自动计算受影响用户/下游设备 → 推荐最优隔离阀门组合 | GNN 图神经网络：基于管网拓扑 + 管径/压力/流速参数，自动推演影响范围和最优关阀方案 |
| `<LeakagePlume>` | 泄漏扩散模拟：燃气泄漏时，根据风向/风速/地形/建筑阻挡，动态生成危险区域多边形 | 简化高斯扩散模型（非 CFD，浏览器可运行） + 气象数据实时接入 |
| `<PipelineHealth>` | 管线健康评估：综合使用年限/材质/土壤腐蚀性/历史事故，生成管线风险热力图 | 评分模型（规则+统计，非黑箱 ML，甲方更信任） |

#### NLPG 场景示例

| 业务人员输入 | 系统行为 |
|-------------|---------|
| "朝阳区所有使用超过 20 年的铸铁燃气管" | 生成 `WHERE material='铸铁' AND install_date < '2006-01-01' AND district='朝阳区'` + 空间过滤 |
| "这个阀门关了之后，下游影响哪些小区？" | 自动识别最近阀门 → 图遍历下游拓扑 → 关联用户表 → 地图高亮 |
| "昨天下午的燃气报警集中在哪个区域？" | 时间范围 + 报警点位 → 空间聚类 → 热力图渲染 |

#### 私有化部署要点

- 管网数据属于城市生命线，**必须私有化**
- 推荐方案：PostGIS + Martin 瓦片服务部署在客户内网，MapLibre 前端通过内网 CDN 加载
- AI 模型（GNN 推演）使用 ONNX Runtime 本地推理，**不走云端**

### 2.2 新型电网（输电/配电/用电）

> **关键词：层级拓扑 × 负荷预测 × 停电管理**

#### 行业特征

- 电网是天然的 **树状/辐射状拓扑**（发电→输电→变电→配电→用电），层级清晰
- 数据相对规范（国网/南网有统一数据模型），但量极大（百万级设备）
- 核心痛点：故障快速定位 + 停电范围评估 + 复电路径优化

#### 专属组件

| 组件 | 功能 | AI 加持 |
|------|------|--------|
| `<GridTopology>` | 电网拓扑浏览器：发电→输电→变电→配电→户的层级钻取，支持设备卡片弹窗 | — |
| `<OutageAnalyzer>` | 停电分析器：选择故障设备 → 自动计算停电范围 → 列出受影响用户数/重要用户 | 图遍历 + 供电路径分析（经典算法，不用 RL） |
| `<LoadHeatmap>` | 负荷热力图：按台区/线路实时展示负荷率，红色=过载，蓝色=轻载 | 时序预测：基于历史负荷曲线 + 天气预报 + 节假日因子，预测未来 24h 负荷热点 |
| `<PatrolRoute>` | 巡检路径优化：根据设备位置/道路/历史故障率，规划最优巡检路线 | 经典 TSP/VRP 算法（不需要 RL） |

#### NLPG 场景示例

| 业务人员输入 | 系统行为 |
|-------------|---------|
| "查出负载率超过 80% 的 10kV 线路" | 生成属性过滤 + 空间范围限定 |
| "这次台风可能影响哪些线路？" | 台风路径预测叠加 → 识别路径两侧 5km 内线路 → 按电压等级分层展示 |
| "这个变电站下面有多少户居民？" | 拓扑遍历 → 关联用户表 → 返回统计 |

#### 与电网 GIS 的差异化

| 维度 | 现有方案（SuperMap/省电力 GIS） | 本方案 |
|------|-------------------------------|--------|
| 部署 | C/S 架构为主，Web 端弱 | 纯 Web，浏览器即用 |
| 授权 | 按节点收费，百万级 | 开源，零授权费 |
| 交互 | 传统 GIS 操作 | AI Copilot 自然语言生成 + NLPG |
| 离线 | 需要 VPN/专线 | 天然支持离线瓦片 |

### 2.3 水网（引调水/防洪排涝/供水）

> **关键词：水系拓扑 × 水文推演 × 汛期指挥**

#### 行业特征

- 水系数据天然连续（河流是线要素，流域是面要素），适合 GIS 可视化
- 季节性强：汛期（6-9 月）是绝对高峰，系统必须"开箱即用"不能临时搭建
- 推演需求刚性：洪水淹没范围、水库调洪效果必须有模型支撑

#### 专属组件

| 组件 | 功能 | AI 加持 |
|------|------|--------|
| `<RiverSystem>` | 水系拓扑图：河流→水库→闸站→堤防的层级关系，支持顺流/逆流钻取 | — |
| `<FloodInundation>` | 洪水淹没模拟：输入降雨量/上游来水 → 动态生成淹没范围多边形 → 叠加人口/资产数据计算损失 | 简化水文模型（SCS-CN + 谢才公式） + DEM 地形分析。**这是本方案里唯一真正需要物理模型推演的场景** |
| `<DamOperation>` | 水库联合调度：多个水库的蓄泄方案可视化对比 | 多目标优化（防洪+发电+供水） → Pareto 前沿展示 |
| `<RainfallForecast>` | 降雨预测地图：接入气象预报数据，按流域单元展示未来 24/48/72h 降雨量 | 雷达外推 + 数值预报融合 |

#### NLPG 场景示例

| 业务人员输入 | 系统行为 |
|-------------|---------|
| "上游降雨 80mm 时，下游哪些堤段会超警？" | 降雨→径流→水位计算 → 超警阈值比对 → 地图高亮 |
| "如果开 3 号闸放水，下游 10 公里内有哪些村庄？" | 模拟放水 → 沿河道缓冲区分析 → 叠加居民点数据 |
| "过去 24 小时降水量最大的 10 个雨量站" | 时序数据聚合 → 排序 → 地图标记 |

### 2.4 交通网（公路/铁路/城市交通）

> **关键词：实时路况 × 流量分析 × 事件响应**

#### 行业特征

- 数据时效性要求最高（路况每分钟变化）
- 数据源多元（交管、路政、导航平台、视频 AI）
- 核心价值是 **实时** + **预测**，不是静态展示

#### 专属组件

| 组件 | 功能 | AI 加持 |
|------|------|--------|
| `<RoadNetwork>` | 路网编辑器：支持路段属性编辑（限速/车道数/路面状况），实时路况叠加 | — |
| `<TrafficFlow>` | 交通流量可视化：路段按流量/速度着色 + 拥堵传播动画 | 拥堵预测：基于历史 + 实时 → 预测未来 15/30/60min 拥堵趋势 |
| `<IncidentMap>` | 事件响应图：事故/施工/管制点位 + 自动计算影响范围（拥堵扩散区域） | 事件关联分析：自动匹配附近摄像头画面、救援资源、绕行方案 |
| `<TransitHeatmap>` | 公共交通热力图：公交/地铁客流 OD 矩阵可视化 | 客流预测 + 线路优化建议 |

#### NLPG 场景示例

| 业务人员输入 | 系统行为 |
|-------------|---------|
| "当前全网平均速度最低的 10 条路段" | 实时数据聚合 → 排序 → 地图高亮 |
| "这个事故点 3 公里内有多少个摄像头？" | 空间缓冲区查询 → 关联摄像头表 → 地图标记 |
| "预测未来 1 小时三环的拥堵变化" | 时序预测模型 → 输出趋势曲线 + 地图动态着色 |

#### 与交通大厂的差异化

不做"大而全的交通大脑"（百度/高德有数据优势），聚焦：
- **交管部门的 Web 端轻量化工具**（不需要装 SuperMap Desktop）
- **事故应急指挥的快速搭建**（MapCopilot 10 分钟生成一个事故态势图）
- **铁路/公路养护的巡检管理**（离线 + 移动端）

### 2.5 算力网（数据中心/边缘节点/光缆路由）

> **关键词：资源拓扑 × 利用率监控 × 调度优化**

#### 行业特征

- 数据本身是"数字原生"的（IT 系统天然产生指标数据），接入门槛低
- 地理分布 + 网络拓扑双重关系
- "十五五"新增投资 4 万亿，市场正在爆发

#### 专属组件

| 组件 | 功能 | AI 加持 |
|------|------|--------|
| `<ComputeNodes>` | 算力节点地图：数据中心/边缘节点分布 + 点击查看详情（算力/存储/利用率） | — |
| `<FiberRoute>` | 光缆路由可视化：节点间的光缆连接 + 按带宽/利用率着色 | — |
| `<ResourceScheduler>` | 算力调度面板：按区域/算力类型（GPU/CPU）筛选 → 拖拽分配 | 供需预测：基于历史使用模式 + 新增 AI 训练任务，预测未来算力需求 |
| `<LatencyMap>` | 延迟热力图：用户端到各算力节点的网络延迟 → 推荐最优接入节点 | — |

#### NLPG 场景示例

| 业务人员输入 | 系统行为 |
|-------------|---------|
| "利用率低于 30% 的 GPU 节点" | 属性过滤 → 地图展示 → 点击查看详情 |
| "北京到上海之间有哪些光缆路由？" | 空间查询 → 路径拓扑分析 → 地图高亮 |
| "预测下个月华东区的算力缺口" | 时序预测 + 供需分析 → 输出报表 + 地图热力 |

#### 算力网的特殊价值

算力网客户（运营商/算力企业）技术能力强，但需要：
- **对外展示工具**：给投资人/甲方看算力布局的交互式地图大屏
- **内部运维工具**：快速定位故障节点 + 路由切换
- **销售工具**：客户查看附近可用算力节点

### 2.6 通信网（基站/光缆/机房）

> **关键词：覆盖分析 × 信号质量 × 网络优化**

#### 行业特征

- 数据维度多（基站属性 + 信号强度 + 用户数 + 故障状态 + 覆盖范围）
- 需要精确的 **覆盖分析**（信号传播模型 + 地形遮挡）
- 运营商对大屏展示有强烈品牌定制需求

#### 专属组件

| 组件 | 功能 | AI 加持 |
|------|------|--------|
| `<CellCoverage>` | 基站覆盖地图：按基站类型（宏站/微站/室分）展示覆盖范围 + 信号强度色谱 | — |
| `<SignalQuality>` | 信号质量热力图：基于路测数据/用户上报数据，渲染 RSRP/SINR 等指标 | 信号质量预测：基于基站参数 + 地形数据 + 覆盖模型 → 预测盲区 |
| `<NetworkHealth>` | 网络健康度面板：基站在线率/告警分布/故障统计 | 故障根因分析：关联多维度数据（温度/负载/邻区干扰） → 推荐排查方向 |
| `<CapacityOptimizer>` | 容量优化建议：识别高负荷基站 → 推荐扩容/新建/参数调整方案 | 负荷预测 + 仿真对比 |

#### NLPG 场景示例

| 业务人员输入 | 系统行为 |
|-------------|---------|
| "5G 基站中近 7 天故障率超过 5% 的" | 时序聚合 + 属性过滤 → 地图标记 |
| "这个区域内 4G 和 5G 覆盖的重叠率" | 覆盖范围叠加分析 → 着色展示 |
| "周边 2 公里内哪些基站负载最高？" | 空间查询 + 排序 → 地图热力 |

#### 运营商大屏的品牌化需求

通信网客户最在意大屏视觉效果（汇报/展示场景多）。利用 **C5 智能样式生成**：
- 上传运营商品牌色手册 → 自动生成匹配的品牌化 style.json
- 三大运营商（移动/联通/电信）各出一套预设主题模板
- 支持一键切换：白天/夜间模式、城区/郊区模式

## 四、差异化竞争定位

### 不做什么（明确边界）

| 不做 | 原因 |
|------|------|
| 不做底图数据 | 天地图/高德已经覆盖，我们做渲染引擎不做数据 |
| 不做全功能 GIS 平台 | 不和 SuperMap/ArcGIS 全面竞争，聚焦 Web 端轻量化场景 |
| 不做"物理引擎模拟" | 流体力学/CFD 走后端预计算，不在浏览器跑 |
| 不做 RL/黑箱 AI | 电网/管网客户需要可解释的推演结果，用规则+图遍历+传统算法 |

### 做什么（明确价值）

| 做 | 价值 |
|----|------|
| **开源可私有化** | 安全可控 = G 端/央国企采购硬门槛 |
| **AI 辅助开发** | Copilot + NLPG = GIS 开发效率翻倍，降低项目交付成本 |
| **轻量化 Web 端** | 一个浏览器搞定，不需要装 SuperMap Desktop |
| **六张网复用** | 共性底座写一次，六张网只需开发行业组件 → 交付成本逐网递减 |
| **快速定制** | 样式生成 + Copilot = 甲方提需求 → 10 分钟出 Demo |

### 竞品对照

| 维度 | SuperMap/中地 | 高德/百度 | **本方案** |
|------|-------------|---------|-----------|
| 定位 | 全功能 GIS 平台 | 导航/位置服务 | **Web 端行业地图引擎** |
| 部署 | 重（桌面端/私有化部署复杂） | 纯云端 | **轻量（纯 Web + 离线）** |
| 开源 | ❌ | ❌ | ✅ |
| AI | ❌ | 有限（搜索推荐） | ✅（Copilot + NLPG + 推演） |
| 行业深度 | 深（但每行业一套独立产品） | 浅 | **中（共性复用 + 行业组件可插拔）** |
| 客制化 | 贵（按项目报价） | 不支持 | **快（AI 辅助 + 样式生成）** |

## 五、落地路径建议

### Phase 0 — 基础引擎 + 共性服务层 (M1-M3)
- MapLibre 定制引擎（离线、投影、Shader）
- MapCopilot v1（限定 5 类核心交互）
- GeoAI 智能数据入图管线
- NLPG 接口 v1（含 SQL 校验层）

### Phase 1 — 地下管网 MVP (M4-M6)
选择地下管网作为第一个行业落地：
- `<PipelineTopology>` + `<BurstSimulator>`（图遍历版）
- 接入 1 个试点城市的燃气/供水管网数据
- 产出：可在客户现场演示的管网巡检+应急推演 Demo

### Phase 2 — 电网 + 水网并行 (M7-M9)
- `<GridTopology>` + `<OutageAnalyzer>` + `<LoadHeatmap>`
- `<FloodInundation>`（简化水文模型）
- NLPG v2（支持更多空间函数）
- 各出 1 个试点 Demo

### Phase 3 — 交通/算力/通信 (M10-M12)
- 基于前两阶段积累的行业组件模板，加速交付
- `<TrafficFlow>` + `<ComputeNodes>` + `<CellCoverage>`
- AI Debug 工具 + 样式生成器 v2
- 正式发布 v1.0 GA

### 推荐的"第一枪"策略

> **不要同时铺六张网。** 选 **地下管网** 打第一枪：
> - 投资规模明确（~5 万亿）
> - 爆管/泄漏推演是刚需且有政策驱动（城市生命线工程）
> - PRD 原有能力最匹配
> - 试点周期短（3 个月出 Demo）
> - 做出标杆案例后，其他五张网的客户会主动找上门
