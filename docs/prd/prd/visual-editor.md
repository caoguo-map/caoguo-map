## 一、产品定位

### 1.1 一句话定位

> **像搭积木一样搭建地图大屏——拖一个地图、拖几个卡片、配一下数据源，30 秒出一个大屏。**

### 1.2 类比

| 产品 | 做什么 | 我们做什么 |
|------|--------|-----------|
| Notion | 拖拽块搭建文档 | 拖拽块搭建大屏 |
| Retool | 拖拽组件搭建后台 | 拖拽组件搭建地图大屏 |
| Grafana | 拖拽面板搭建监控看板 | 拖拽面板搭建行业地图大屏 |
| 游戏关卡编辑器 | 拖拽元素搭建游戏关卡 | 拖拽元素搭建大屏场景 |

### 1.3 核心价值

| 角色 | 之前 | 之后 |
|------|------|------|
| **前端工程师** | 手写 Vue 组件拼装大屏 | 用编辑器生成 JSON，引擎自动渲染 |
| **产品经理** | 画 Axure 原型给开发看 | 自己拖拽搭出可运行的大屏 Demo |
| **甲方决策者** | 看 PPT 想象大屏效果 | 看到真实可交互的大屏 |
| **外包商** | 每个项目重新开发 | 编辑器里换个数据源就是一个新项目 |

### 2.2 核心流程

```
用户拖拽组件到画布
    ↓
```

### 3.6 系统自检（SystemCheck）

编辑器内置自检面板，交付前一键排查"能不能跑起来"的常见问题，避免大屏投产后才发现环境/数据问题。

自检分两段：**静态体检**（不发起网络）+ **连通性检查**（真实请求）。

| # | 检查项 | 说明 | 状态 |
|---|--------|------|------|
| SC-1 | 概览统计 | 场景数 / 节点数 / 数据源数 | ✅ 已落地 |
| SC-2 | 配置完整性 | 无场景、节点 id 重复、节点越界出画布 | ✅ 已落地 |
| SC-3 | 数据绑定一致性 | 节点/图层的「悬空数据源引用」与「数据源未配置」 | ✅ 已落地 |
| SC-4 | 底图提示 | 使用天地图底图时提示 token 配置要求（info 级） | ✅ 已落地 |
| SC-5 | 数据源连通性 | 逐个测试已配置数据源，输出状态与耗时（error/ok 分级） | ✅ 已落地 |
| SC-6 | 一键修复引导 | 对可自动处理的问题给出修复入口 | 🟡 部分（当前以提示与跳转为主） |

## 四、数据绑定系统

### 4.1 数据源配置

每个可数据驱动的组件都需要绑定数据源：

```
┌─ 数据源配置 ──────────────────────┐
│                                    │
│  来源类型:                          │
│  ○ 静态数据（手动输入）             │
│  ○ API 接口（REST）                │
│  ○ WebSocket（实时推送）            │
│  ○ 设备图层（从图层获取）            │
│                                    │
│  ── API 接口配置 ──                 │
│  接口地址:  [/api/devices    ]      │
│  请求方式:  [GET ▼]                │
│  刷新间隔:  [5 秒 ▼]               │
│  Headers:                           │
│  ├─ Authorization: [Bearer xxx]    │
│  └─ [+ 添加]                       │
│                                    │
│  ── 字段映射 ──                     │
│  数据路径:  [data.devices    ]      │  ← JSONPath
│  值字段:    [data.pressure   ]      │
│  标签字段:  [name            ]      │
│                                    │
│  [测试接口]  [预览数据]              │
│                                    │
└────────────────────────────────────┘
```

> **本节初稿只列了 4 种来源类型**（静态 / REST / WebSocket / 设备图层）。实现已扩展为 **14 种**，并引入后端代理取数。以下为 V1.1 补齐的口径。

#### 4.1.1 支持的数据源类型（`DataSourceType`）

| 分类 | 类型 | 说明 | 取数方式 |
|------|------|------|----------|
| 静态 | `static` | 手动输入的静态数据 / JSON | 前端直接读取 |
| 静态 | `file`（Excel / CSV） | 上传 `.xlsx` / `.csv`，前端解析（xlsx 走动态 import 懒加载） | 前端解析 |
| 网络 | `rest` | REST 接口轮询（可配刷新间隔、Headers、JSONPath） | 前端直连 |
| 网络 | `websocket` | WebSocket 实时推送 | 前端直连 |
| 网络 | `webhook` | Webhook 回调写入 | 前端/代理 |
| 业务 | `device-layer` | 绑定画布内的设备图层，从图层取数 | 内部联动 |
| 数据库 | `mysql` / `postgresql` / `oceanbase` / `clickhouse` / `influxdb` / `dameng`（达梦） | SQL 查询取数 | **经后端代理**（不暴露库凭据到浏览器） |

#### 4.1.2 后端代理与凭据安全

数据库类数据源**不在浏览器直连**，统一经后端代理转发：

```
浏览器 ──(数据源 id + SQL + 参数)──▶ 后端代理服务（默认 http://localhost:8787）
                                        │  持有 DB 连接串/账号密码
                                        ▼
                                    MySQL / PG / OceanBase / ClickHouse / InfluxDB / 达梦
```

- 编辑器侧配置项：**「数据源 → 代理基地址」（`proxyBase`）**，默认 `http://localhost:8787`。
- 数据库密码等敏感字段**仅保存在本地草稿**，导出 JSON 时默认剔除（见 §7.3）。

#### 4.1.3 字段映射

沿用上图的「数据路径（JSONPath）/ 值字段 / 标签字段」三元组；数据库类型额外支持「SQL → 结果列 → 字段映射」。

**图表字段来源设备 Schema 下拉（✅ 已落地，2026-08-28）**：绑定 `device-layer` 类型数据源且设备已配置 `DeviceSchema` 时，图表类组件（trend-chart / bar-chart / pie-chart / gauge-chart / wind-rose）的「值字段 / 标签字段 / 分组字段」改为**从 schema 字段定义下拉**选取，而非手填字符串，避免字段名拼写错误。

**字段默认值自动填充（✅ 已落地，2026-08-28）**：选中 schema 字段后，组件按字段类型回填合理缺省——数值字段默认映射 `value` 并适配折线/柱状/仪表盘，枚举/分类字段默认映射 `label` 并适配饼图/玫瑰图；无需逐字段手动配置。

### 4.2 组件间数据联动

```
设备图层 (数据源)
    ↓ 点击设备
设备详情面板 (自动接收选中设备数据)
    ↓ 数据字段
数据指标卡 (绑定 设备图层.选中设备.压力)
    ↓ 数据字段
折线图 (绑定 设备图层.选中设备.历史压力)
```

编辑器支持**拖拽连线**建立数据绑定关系：

#### 4.2.1 实时刷新视觉反馈（✅ 已落地，2026-08-28）

设备图层 / 指标卡 / 图表类组件在轮询刷新（`refreshInterval`）拿到新数据时，触发轻量视觉反馈：地图标记脉冲高亮、卡片边框 1 次渐变描边、图表数据点闪动。反馈随刷新节流（默认 ~1s 去抖），避免高频刷新造成视觉抖动。

#### 4.2.2 告警阈值本地规则着色（✅ 已落地，2026-08-28）

告警阈值在组件本地按「正常 / 警告 / 严重」三档规则着色与脉冲——地图标记、指标卡、告警列表均依据数值阈值切换 `ok / warn / danger` 配色与动画强度，无需依赖后端告警流。阈值规则随节点 JSON 导出，运行端独立可复现。

#### 4.2.3 跨场景告警面板（✅ 已落地，2026-08-28）

预览模式下挂载全局 `AlertPanel`：聚合当前场景告警、支持「定位」跨场景飞向告警设备（基于 `deviceStore.selectedDeviceId` 的 `watch(flyTo)` 跨场景重定位）、并支持声音提示与标记闪烁（`alertSoundEnabled` / 脉冲动画）。

### 5.2 JSON 核心概念

| 概念 | 说明 |
|------|------|
| `canvas` | 画布尺寸和背景 |
| `scenes[]` | 场景数组（每个场景 = 一个大屏页面） |
| `layers[]` | 地图图层（设备标记等需要在地图上渲染的） |
| `components[]` | UI 组件（面板、卡片、图表等叠加在地图上的） |
| `position` | 绝对定位 `{ x, y, w, h }` |
| `dataSource` | 数据源配置 |
| `config` | 组件专属配置 |
| `style` | 自定义样式覆盖 |
| `trigger` | 显示触发条件（如 `device-click` 时显示详情面板） |

### 7.2 独立运行

导出的 JSON + 渲染引擎 = 一个独立可运行的大屏 HTML：

```html
<!-- 用户只需这一行 -->
<script src="https://map.hb.cn/caoguo-runtime.js"></script>
<script>
  CaoguoMap.renderFromJSON('/config/my-dashboard.json', '#app')
</script>
```

渲染引擎读取 JSON → 自动创建地图 → 自动放置组件 → 自动绑定数据 → 大屏运行。

### 7.3 导出与安全（脱敏分层）

大屏 JSON 会在「本地草稿 / 下载文件 / 投放大屏」三种场景间流转，安全口径必须分层：

| 场景 | API | 敏感字段（`proxyBase`、数据源 `password`） |
|------|-----|------------------------------------------|
| 本地草稿（localStorage 自动保存） | `exportJSON({ includeSecrets: true })` | **保留**，便于本地续编、刷新不丢配置 |
| 下载 JSON / 投放大屏 | `exportJSON()`（默认） | **剔除**，产物可安全分发 |

配套约束：数据库/Webhook 类数据源经后端代理取数（§4.1.2），库凭据**只存本地草稿**，不进导出产物。

| 形态 | 组件 | 位置 | 对外可用 |

| 按 `type` 内联渲染 | `data-card` / `stat-row` / `data-grid` / `progress-card` / `soil-profile` / `alert-list` / `trend-chart` / `bar-chart` / `pie-chart` / `gauge-chart` / `wind-rose` / 容器类 | `ComponentView.vue` 的 `v-if` 分支 | ❌ 无独立组件文件 |

**关键约束**：5 个独立组件的 props 统一为 `{ node: ComponentNode }` —— 它们是**画布节点渲染器**，配置全部来自节点 JSON，取数依赖编辑器 store（`useEditor` / `useDeviceData`），**脱离 `Editor` 无法工作**。因此它们不是通用 UI 组件，当前形态不适合直接对外发布。

### 14.3 规划中的三个组件

### 14.4 未来若要独立发包（触发条件与路径）

**触发条件**：出现"只用组件库、不装编辑器"的真实需求。

**实施路径**：
1. 新建 `packages/components`；
2. 组件接口从 `node: ComponentNode` 改为业务 props（如 `DeviceList` 接收 `devices: DeviceItem[]`）；
3. 把 `ComponentView.vue` 的内联分支抽成独立组件；
4. 解耦 store 依赖（数据改为 props 注入或 `provide/inject`）；
5. 独立发布 `@caoguo/map-components`。

> 在此之前，**不要对外承诺组件库的独立 API**。
