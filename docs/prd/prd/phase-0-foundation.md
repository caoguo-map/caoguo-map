## 一、背景与问题

### 1.1 为什么做 Phase 0

草果地图（caoguo-map）面向「六张网」（管网、电网、水网、交通网、算力网、通信网），目标是成为开源、可私有化的地图引擎与 AI 空间智能服务。Phase 0 是整条产品线的技术底座，聚焦三件事：

1. **引擎可用**：一个标准 Web 应用能通过 CDN 或 npm 引入，在 5 行代码内渲染出带底图的地图，且支持国内坐标系（CGCS2000 / GCJ-02 / WGS84）。
2. **共性服务可复用**：把「坐标系纠偏、天地图接入、离线瓦片、主题样式」这些每个行业项目都要重复造的轮子，一次性做成可插拔能力。
3. **能力可展示**：落地页、文档站、演示中心三站，让 G 端 / 央国企决策者与 GIS 开发者在 30 秒内理解产品价值并上手。

### 1.2 现状与缺口

| 维度 | Phase-0 现状 | 缺口 |
|------|-------------|------|
| 引擎 | `@caoguo/maplibre` 已实现 8 大模块（CRS/天地图/离线瓦片/SW 缓存/控件/辉光/LOD/主题），测试 75 passed | 尚未发布到 npm（本任务处理中）；3D 地形、通用 Shader 框架未实现 |
| 展示 | 落地页（V2.0）、文档站（29 页）、演示中心（D5 串联闭环）均已落地 | 无 |
| AI 能力 | demo 有 Copilot UI；`packages/ai` 已实现 MapCopilot / NLPG / GeoAI 三模块代码 | 接口联调待 swagger 就绪（D5/D6/D7 代码层已落地，见下方状态） |
| 组件包 | `@caoguo/theme`（主题）、`@caoguo/maplibre-pipeline`（管网，Phase 1 交付物）已就位 | pipeline 包尚为半成品（burst 已实现，health/leakage/topology/nlpg 占位），build 待修复 |

### 1.3 本 PRD 解决的问题

- 把「Phase 0 要交付什么、做到什么程度、怎么验收」固化为可评审、可验收的规划文档。
- 消除「PRD 承诺」与「代码现实」的漂移：所有「已落地」条目均可在 `packages/` 与 `apps/` 中查证。

## 二、阶段目标

在 3 个月内完成草果地图的基础引擎定制和共性利他服务层搭建，使得：

1. 一个标准 Web 应用可通过 CDN 或 npm 引入，在 5 行代码内渲染出带有底图的地图 ✅
2. 地图支持国内坐标系（CGCS2000 / GCJ-02 / WGS84）无缝切换 ✅
3. 支持离线瓦片加载（无网络环境下可用） ✅
4. 开发者可通过自然语言对话生成地图代码（MapCopilot v1） ❌
5. 非标地址数据可通过智能管线自动空间化入图（GeoAI v1） ❌
6. 业务人员可通过自然语言查询 PostGIS 空间数据（NLPG v1） ❌

> 说明：目标 1/2/3 为「引擎能力」，已全部落地；目标 4/5/6 为「AI 能力」，Phase 0 内未实现，顺延至 Phase 1 与管网场景协同开发（对应 D5/D6/D7）。

## 三、范围与非目标

### 3.1 范围（本期 PRD 覆盖）

- `@caoguo/maplibre` 定制引擎（坐标系 / 天地图 / 离线瓦片 / 主题 / 控件 / 辉光 / LOD）。
- `@caoguo/theme` 主题样式（暗 / 亮矢量主题 + tokens.css）。
- 落地页、技术文档站、演示中心三站。
- MapCopilot / GeoAI / NLPG 的**需求定义**（实现顺延至 Phase 1）。

### 3.2 非目标（本期明确不做）

| 非目标 | 原因 |
|--------|------|
| 自研渲染内核（fork maplibre-gl 并重写 WebGL） | 做薄封装 + 插件（addProtocol / CustomLayer / transformRequest），maplibre-gl 设为 peerDependency，降低维护成本 |
| 3D 地形渲染（F-1.5） | P2 优先级，Phase 0 不做 |
| 通用 Shader DSL / 编辑器 | 仅交付「管线辉光」CustomLayer 一个垂直 Shader 场景（F-1.3 部分落地） |
| 六张网行业专题图层 | 属 Phase 1-3（管网 Phase 1，电/水 Phase 2，交通/算力/通信 Phase 3） |
| MapCopilot / GeoAI / NLPG 的实现 | 需求已定义，实现顺延 Phase 1 |
| 多语言 i18n | 首期仅中文 |

### 3.3 能力边界（对外披露）

- 引擎为「轻量封装层」：复用 MapLibre GL 能力，已注入坐标系纠偏、天地图底图、离线瓦片、辉光 / LOD / 控件等增强；尚未包含自研渲染内核、三维地形、矢量切片服务。
- 离线能力分两层：**业务离线瓦片**（T4，IndexedDB + `caoguo-offline://` 协议层短路，不发网）与 **SW 二级缓存 + 空气隔离拦截**（T5，Cache API，线上瓦片可缓存、可禁网）。两者定位不同，须分别理解。
- 坐标系口径：引擎默认以 WGS84 为渲染基准，业务 GCJ02 / CGCS2000 数据通过 `dataCRS` + `transformToMap` 在入图前纠偏；天地图为 CGCS2000 / Web Mercator，显示尺度等价 WGS84。

| G-3 | 坐标系判断 | 自动判断数据的坐标系（GCJ-02/WGS84/CGCS2000） | ❌ |
| G-4 | 批量地理编码 | 10 万条地址可在 5 分钟内完成编码 | ❌ |
| G-5 | 地图预览 | 编码完成后直接在地图上预览结果 | ❌ |

#### 5.6.3 技术方案

```
CSV/Excel 上传
    ↓
表头识别（正则 + 列名语义分析）
    ↓
地址列提取
    ↓
地址标准化（词典匹配 + 模糊匹配 + 词向量相似度）
    ↓
地理编码（天地图/高德 API 或本地坐标库）
    ↓
坐标系判断与转换
    ↓
GeoJSON 输出 → 地图渲染
```

**注意**：v1 使用传统 NLP 方案（正则+词典+规则），不依赖大模型，保证速度和可控性。

#### 5.6.4 验收标准

- [ ] 支持 CSV / Excel (.xlsx/.xls) 格式
- [ ] 常见表头（地址/位置/地名/名称/经纬度）自动识别率 ≥ 90%
- [ ] 标准中文地址解析成功率 ≥ 90%
- [ ] 口语化地址（如"光谷那边""汉口火车站附近"）解析成功率 ≥ 60%
- [ ] 10 万条数据编码耗时 < 5 分钟
- [ ] 支持 GCJ-02 ↔ WGS84 自动转换

> 现状：完全未实现，顺延 Phase 1（管网数据接入将作为首个落地场景）。

### 5.7 NLPG v1 查询接口

#### 5.7.1 需求描述

业务人员输入自然语言，系统自动生成 PostGIS 空间查询并返回结果。

#### 5.7.2 功能点

| # | 功能 | 描述 | 状态 |
|---|------|------|------|
| N-1 | 文本→SQL | 自然语言转 PostGIS SQL | 🟡 仅 pipeline 有意图识别占位（`nlpg/`） |
| N-2 | 空间关系 | ST_Intersects / ST_Contains / ST_Buffer / ST_DWithin | ❌ |
| N-3 | 属性过滤 | 支持 AND/OR 条件组合 | ❌ |
| N-4 | 结果可视化 | SQL 执行结果自动渲染到地图 | 🟡 demo 有关键词解析驱动地图 |
| N-5 | SQL 校验 | 所有生成的 SQL 必须通过安全校验层 | ❌ |

#### 5.7.3 SQL 校验层（关键安全机制）

```
LLM 生成的 SQL
    ↓
语法校验（SQLParse）
    ↓
白名单表检查（只允许查询授权表）
    ↓
危险操作拦截（DROP/DELETE/UPDATE/INSERT 全部拒绝）
    ↓
参数化执行（防止 SQL 注入）
    ↓
超时控制（单查询 < 10 秒）
    ↓
执行 → 返回 GeoJSON
```

#### 5.7.4 验收标准

- [ ] 简单属性查询意图识别准确率 ≥ 90%
- [ ] 空间关系查询意图识别准确率 ≥ 80%
- [ ] 混合查询（空间+属性）意图识别准确率 ≥ 75%
- [ ] 生成的 SQL 100% 通过安全校验
- [ ] 查询响应时间 P95 < 3 秒
- [ ] 查询结果自动渲染到地图，支持点/线/面三种要素类型

> 现状：demo 有「关键词解析 → 高亮 + 飞行定位」的演示，但**非真实 NLPG**（无 SQL 生成、无 PostGIS、无校验层）。完整能力顺延 Phase 1。
